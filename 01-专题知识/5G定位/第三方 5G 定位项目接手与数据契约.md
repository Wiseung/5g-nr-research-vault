# 第三方 5G 定位项目接手与数据契约

> [!abstract] 当前工作定位
> 先把嘉琪已经实现的 PRACH 检测链路跑通、读懂并补齐可验证的输入/输出，再进入 C-RNTI 驱动的 PDCCH/PDSCH 解析，最后才把多站时间观测接入 UL-TDOA。每一阶段都要有可回放数据和失败原因。

## 1. 三阶段边界

| 阶段 | 目标 | 成功证据 | 不应提前承诺 |
|---|---|---|---|
| 1. RA/PRACH | 检测前导、定位 occasion、估计时延/功率，并尝试关联 RAR/临时 RNTI | 单站回放、相关峰、配置快照、失败分类 | PRACH 单独解出 C-RNTI |
| 2. 控制/数据 | 用有限 RNTI 候选盲搜 PDCCH，解析 DCI 并驱动 PDSCH/PUSCH 资源提取 | 候选日志、DCI 字段、资源命中、CRC/TB 状态 | 无配置时盲解所有用户/所有 PDSCH |
| 3. 多站定位 | 对同一用户事件形成跨站 RTOA/TDOA 并解算位置 | 时钟/硬件校准、TDOA 残差、位置误差和实时延迟 | 没有同步和几何验证的实时定位精度 |

## 2. 与嘉琪交接时必须拿到的东西

### 代码与版本

- MATLAB 版本、5G Toolbox 版本、工程入口脚本和依赖路径。
- 一次完整运行命令、输入文件格式、输出文件格式和随机种子。
- PRACH 配置来源：手工参数、SIB1/RRC 导出还是设备元数据。
- 已知通过样本、已知失败样本和对应的日志。
- 采样率、中心频率、天线通道顺序、I/Q 数据类型和时间戳定义。

### 协议与网络配置

- 小区 ID、SCS、初始/活动 BWP、Point A 和载波带宽。
- PRACH 格式、根序列、循环移位、occasion、SSB 关联和 2-step/4-step 类型。
- CORESET、搜索空间、PDCCH 候选、DCI 格式和 RNTI 候选来源。
- TDD slot format、flexible/guard 符号和上下行切换配置。
- 是否能看到 RAR（PDSCH 承载的 MAC 内容）、Msg3、Msg4；哪些上层 PDCP/RRC/业务内容受安全保护而不可见。RAR/PHY 解码失败需单独记录。

### 硬件与采集

- 每站 `station_id`、坐标、天线位置、公共时钟来源和 PPS/PTP 状态。
- RF、线缆、滤波器、抽 decimation 和数字下变频的固定延迟。
- 多站启动时间、采集时长、丢样/溢出计数和温度/时钟漂移记录。
- 同一事件的跨站文件命名或 `capture_id` 规则。

## 4. 第一阶段的实际验收

1. 能在单站样本中重现嘉琪的 PRACH 检测结果。
2. 把最大相关峰以外的峰、门限、窗口和频偏一起保存。
3. 改变一个输入（前导索引、时延、CFO 或噪声）后，能解释输出变化。
4. 明确当前输出是 `preamble_detected`、`toa_valid` 还是已经有 RAR/临时 C-RNTI 关联。
5. 用非全零、多前导和碰撞样本做负例；不能只用单一成功样本。

## 5. 第二、三阶段的进入门槛

进入 PDCCH/PDSCH 前：

- 已锁定至少一个合法 `carrier/BWP/CORESET/search-space` 快照。
- 已知一个测试 C-RNTI 或能从 RA 链形成有限候选池。
- 正确候选、错误 RNTI、错误资源各有一个可回放样本。

进入多站 TDOA 前：

- 三站二维几何、坐标系和参考站已固定。
- 公共时钟、RF delay、滤波群时延和采样率偏差有校准记录。
- 每站能对同一事件输出原始 ToA、峰策略和质量，不只输出最终坐标。

## 6. 交接问题清单

- 当前工程假设的是 2-step 还是 4-step RA？是否支持 CFRA？
- “C-RNTI 已解出”具体指 RAR 的 TEMPORARY-C-RNTI、Msg3 的 C-RNTI MAC CE，还是 Msg4 后的 C-RNTI 状态？
- PDCCH 盲搜的 RNTI 候选从哪里来？是否有 UE 专用 RRC 配置？
- 数据采集设备能否在同一载频连续记录 UL 和 DL，还是按时隙切换触发？
- 定位主观测是 PRACH、PUSCH DM-RS、SRS 还是重构的业务片段？首径策略是什么？
- 三台设备用于二维且已同步的试验，还是要直接做三维/未知钟差？

这些问题的答案要写入 `config_snapshot`，不能只留在口头交接中。

## 7. MATLAB 示例：配置快照校验与事件落盘

先校验必需字段和单位，再把原始事件与配置快照一起保存。缺失值保持为空或 `NaN`，不能用 0 伪装成已测量或已校准。

```matlab
function missing = validateConfigSnapshot(cfg)
% cfg 来自采集工程导出的配置快照，不在校验器中补造默认配置。
required = ["config_id", "matlab_version", "toolbox_version", ...
    "cell_id", "center_frequency_hz", "sample_rate_hz", "scs_khz", ...
    "bwp", "tdd_pattern", "prach_config", "capture_start_time"];
missing = strings(0, 1);

for k = 1:numel(required)
    name = required(k);
    if ~isfield(cfg, name) || isempty(cfg.(name))
        missing(end + 1, 1) = name; %#ok<AGROW>
    end
end

numericFields = ["cell_id", "center_frequency_hz", ...
    "sample_rate_hz", "scs_khz"];
for k = 1:numel(numericFields)
    name = numericFields(k);
    if ~isfield(cfg, name) || ~isnumeric(cfg.(name)) || ...
            ~isscalar(cfg.(name)) || ~isfinite(cfg.(name))
        missing(end + 1, 1) = name; %#ok<AGROW>
    elseif name == "cell_id"
        assert(cfg.(name) >= 0 && cfg.(name) == floor(cfg.(name)), ...
            "cell_id 必须是非负整数");
    else
        assert(cfg.(name) > 0, name + " 必须大于 0");
    end
end
missing = unique(missing, "stable");
end
```

将上面的函数保存为 `validateConfigSnapshot.m`。下面是事件记录脚本：

```matlab
% 示例调用：cfg 是从项目适配器读取的 struct
missingFields = validateConfigSnapshot(cfg);
if ~isempty(missingFields)
    fprintf("配置快照待补字段：%s\n", strjoin(missingFields, ", "));
end
configId = "";
if isfield(cfg, "config_id") && ~isempty(cfg.config_id)
    configId = string(cfg.config_id);
end

event = struct( ...
    "event_id", string(eventId), ...
    "station_id", string(stationId), ...
    "capture_id", string(captureId), ...
    "config_id", configId, ...
    "signal", string(signalName), ...
    "direction", string(direction), ...
    "toa_seconds", NaN, ...
    "timing_offset_samples", NaN, ...
    "association_state", "candidate", ...
    "quality_flags", {strings(0, 1)});

record = struct("config", cfg, "event", event, ...
    "missing_config_fields", missingFields, ...
    "created_utc", datetime("now", "TimeZone", "UTC"));
save(captureRecordPath, "record", "-v7.3");
```

接入实际工程时，`eventId`、`stationId` 等变量来自采集适配器；阶段门槛应根据 `missing_config_fields` 和关联状态判断，而不是静默填充默认值。
