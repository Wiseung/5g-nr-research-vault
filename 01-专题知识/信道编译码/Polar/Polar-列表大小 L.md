# Polar-列表大小 L

> [!abstract] 一句话结论
> SCL 的列表大小 $L$ 表示译码过程中最多保留的候选路径数；增大 $L$ 通常改善有限块长性能，但会增加路径状态存储、排序开销、延迟和功耗，最佳取值需要结合目标 BLER 和硬件预算确定。

## 定义

在每个信息位分裂后，SCL 译码器最多保留 $L$ 条路径：

$$
|\mathcal{P}_t|\le L
$$

其中 $\mathcal{P}_t$ 表示处理到第 $t$ 个叶节点后的候选集合。$L=1$ 时接近 SC；$L>1$ 时允许保留多个可能的早期判决。

配置的 $L$ 是上限，不是每个时刻的实际路径数。若当前信息位之前已有路径被剪枝，或输入状态异常导致列表未填满，实际路径数可能小于 $L$。实验记录应同时保存 `configured_L` 和 `max_active_paths`。

## 性能与复杂度折中

| 增大 L 的影响 | 结果 |
|---|---|
| 候选路径更多 | 正确路径更不容易被早期错误剪枝 |
| 路径状态更多 | 内存占用增加 |
| 候选排序更多 | 计算和延迟增加 |
| CRC 筛选候选更多 | 选择正确路径的机会可能增加 |
| L 超过有效不确定性 | BLER 收益逐渐饱和 |

理论复杂度常以：

$$
\mathcal{O}(L N\log N)
$$

描述主要趋势，但实际实现还受到路径管理、部分排序、内存访问和并行度影响。

比较列表大小时，更有信息量的是记录边际收益：

$$
\Delta\mathrm{BLER}(L)
=\mathrm{BLER}(L/2)-\mathrm{BLER}(L)
$$

以及单位复杂度收益：

$$
G_{\mathrm{eff}}(L)
=\frac{\Delta\mathrm{BLER}(L)}
{\mathrm{Cost}(L)-\mathrm{Cost}(L/2)}
$$

其中 $\mathrm{Cost}(L)$ 可以由平均路径数、排序次数、运行时间或能耗定义。$L$ 增大后的绝对 BLER 改善不能脱离计算和存储代价解释。

## 为什么收益会饱和

如果信道条件较好，正确路径通常很早就具有明显更优的度量，小列表也足够保留它。此时增大 $L$ 主要增加计算，不显著改变 BLER。

在中等 SNR 或短块条件下，多个路径的度量接近，增大 $L$ 才可能明显降低路径剪枝错误。若 LLR 符号、可靠性序列、冻结位或率匹配错误，所有路径都基于错误证据，增加 $L$ 也不能修复接口问题。

## CRC 与 L 的关系

CRC-Aided SCL 的最终候选来自最多 $L$ 条路径。CRC 长度越长，随机错误路径通过 CRC 的概率通常越低，但 CRC 也会占用信息位位置并改变有效信息长度。

需要同时记录：

- 列表大小 $L$。
- CRC 长度和类型。
- 最终候选数量。
- CRC 通过候选数量。
- 选中的路径度量。
- 无候选通过 CRC 的次数。

只报告 $L$ 和 BLER，无法区分性能提升来自候选搜索还是 CRC 筛选。

还应区分三种路径事件：

- 正确路径在剪枝前存在并被保留。
- 正确路径在某一信息位扩展后被剪掉。
- 正确路径一直存在，但最终因 CRC/路径度量选择错误而未输出。

这三个事件对应不同的优化方向，不能都归因于“列表太小”。

建议将实际路径负载定义为：

$$
\bar{L}_{\mathrm{active}}
=\frac{1}{T}\sum_{t=1}^{T}|\mathcal{P}_t|
$$

其中 $T$ 是统计的叶节点或译码实例数量。还应记录尾延迟，例如 $D_{99}$ 或 $D_{\max}$；自适应列表可能降低平均延迟，却因重译码产生更高的尾延迟。

## 自适应列表

某些实现可根据初次译码结果动态调整列表大小：

```text
先以较小 L 译码
    ↓
CRC 通过：直接输出
    ↓
CRC 失败：扩大 L 后重新译码
```

这种策略可能降低平均延迟，但需要记录最坏延迟和重新译码成本。若不同实验使用不同的自适应停止规则，BLER 曲线必须明确统计口径。

自适应列表还应限制最大重试次数和最大总路径预算。对于控制信道，平均延迟下降不能以不可控的 P99/Pmax 延迟为代价；应同时报告首次译码成功率、重试比例和最终失败率。

若一次译码允许的最大列表为 $L_{\max}$、最多重试 $r_{\max}$ 次，则应满足：

$$
L\le L_{\max},
\qquad
r\le r_{\max}
$$

这些约束属于资源和时延边界，不能只在仿真脚本中隐式实现。

## 选择实验

固定 Polar 母码长度、信息长度、CRC、可靠性序列、率匹配、调制、信道和随机种子策略，仅改变 $L$：

| $L$ | BLER | BER | CRC 通过率 | 平均路径数 | 平均延迟 | 内存 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 |  |  |  |  |  |  |
| 2 |  |  |  |  |  |  |
| 4 |  |  |  |  |  |  |
| 8 |  |  |  |  |  |  |
| 16 |  |  |  |  |  |  |

应在低、中、高 SNR 区域都进行比较，并在曲线达到目标 BLER 后再讨论复杂度收益。

## 工程实现注意事项

- 路径状态可使用路径池和写时复制降低复制开销。
- 路径排序应保证相同度量时的稳定性，便于复现。
- LLR 和路径度量要防止定点溢出。
- 路径数不一定始终等于 $L$，冻结位和剪枝会使实际数量变化。
- 统计平均路径数比只报告配置的最大 $L$ 更能反映真实负载。
- 记录路径剪枝次数和峰值活动路径数，避免用配置值替代实际内存访问量。

## 常见误区

1. $L$ 是候选路径数上限，不是每个信息位都必须保留的路径数。
2. 增大 $L$ 不等于增加 Polar 母码长度 $N$。
3. $L$ 和 LDPC 的最大迭代次数不能直接比较为同一复杂度单位。
4. 没有 CRC 时，增大列表可能无法提供同等的候选判决能力。
5. 仅在单个 SNR 点比较 $L$，容易把随机波动误判为稳定收益。

## 最小验证

1. 使用 $L=1$ 与 SC 参考实现对照。
2. 对固定随机信道逐步增加 $L$，检查正确路径是否更少被剪枝。
3. 记录 BLER、CRC 通过率、路径数量、延迟和内存。
4. 翻转 LLR 符号，确认大 $L$ 不能掩盖输入接口错误。
5. 用独立随机种子重复实验，确认收益不是单次样本造成。
6. 统计正确路径被剪枝、CRC 通过、重试和最终失败的比例。
7. 对固定平均延迟或固定最大路径预算比较不同自适应列表策略，而不是只比较配置的 $L$。
