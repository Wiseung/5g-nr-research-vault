# LDPC-译码迭代次数

> [!abstract] 一句话结论
> 最大迭代次数控制 LDPC 译码的性能上限、延迟和能耗；应同时记录最大迭代次数、实际平均迭代次数、早停比例和未收敛块数，不能只报告一个配置值。

## 两种迭代次数

设译码器配置的最大迭代次数为 $I_{max}$。某个码块在第 $I_i$ 轮满足停止条件并结束，则：

- $I_{max}$：允许执行的最大轮数。
- $I_i$：第 $i$ 个码块的实际轮数，通常满足 $1\le I_i\le I_{max}$。
- 平均迭代次数：

$$
\bar{I}=\frac{1}{N_{block}}
\sum_{i=1}^{N_{block}} I_i
$$

如果块直到 $I_{max}$ 仍未通过停止条件，应记录为未收敛或译码失败，并明确统计规则。不要把所有失败块都写成“执行了 $I_{max}$ 轮”后再隐藏失败状态。

若每轮工作量近似为 $W_{\mathrm{iter}}$，则单个码块的实际工作量为：

$$
W_i\approx I_iW_{\mathrm{iter}}
$$

因此平均迭代次数只有在码块结构和每轮工作量相同的实验中，才可以直接作为平均复杂度的代理。不同基图、$Z$、码块长度或 layered/flooding 调度混合时，应报告加权工作量。

## 按码块、传输块和帧统计

一个传输块可能包含多个码块，因此至少区分：

$$
\bar I_{CB}=\frac{1}{N_{CB}}\sum_{r=1}^{N_{CB}}I_r
$$

和一个传输块完成所有码块处理所需的总工作量：

$$
I_{TB,work}=\sum_{r=1}^{C}I_r
$$

如果码块并行处理，实际墙钟延迟更接近：

$$
I_{TB,latency}\approx\max_{1\le r\le C}I_r
$$

因此“平均迭代次数”必须说明是按码块平均、按传输块平均，还是按实际计算量加权。

若第 $i$ 个码块的每轮工作量为 $W_i^{(1)}$，则按计算量加权的平均轮数可写为：

$$
\bar I_{\mathrm{work}}
=\frac{\sum_i I_iW_i^{(1)}}{\sum_iW_i^{(1)}}
$$

它比简单的 $\bar I_{CB}$ 更适合比较不同码块长度或不同基图的实现成本。

## 迭代与译码流程

```text
输入码块 LLR
    ↓
初始化变量/校验消息
    ↓
执行一轮 BP、Min-Sum 或 layered 更新
    ↓
硬判决并检查校验方程或 CRC
    ├── 通过：早停并记录实际轮数
    └── 未通过：继续下一轮
    ↓
达到 I_max：输出失败或当前候选并记录状态
```

早停条件应明确是：

- 所有 LDPC 校验方程满足。
- CB-CRC 通过。
- TB-CRC 通过。
- 消息变化低于阈值。
- 多个条件的组合。

对于多码块传输块，还要说明是每个码块独立早停，还是统一执行固定轮数。

## 早停条件的代价

不同早停条件会改变实际复杂度和统计口径：

| 条件 | 优点 | 注意事项 |
|---|---|---|
| syndrome 为零 | 计算简单、适合每轮检查 | 只说明是合法码字 |
| CB-CRC 通过 | 更贴近码块数据正确性 | 需要提取字段并计算 CRC |
| TB-CRC 通过 | 业务层判据直接 | 多码块时不能只靠一个码块提前判定 |
| 消息变化小 | 可减少部分计算 | 阈值与量化、SNR 相关 |

应记录停止原因，而不是把所有提前结束的块都归类为“译码成功”。

## 性能趋势

一般在其他条件不变时，增大 $I_{max}$ 可以降低尚未收敛的块数量，但收益通常会逐渐饱和：

- 低 SNR：更多迭代可能仍无法恢复，噪声证据不足。
- 中等 SNR：增加迭代往往能够明显改善 BLER。
- 高 SNR：很多块会早停，增加最大值对平均轮数和 BLER 的收益有限。
- LLR 错误、基图错误或率匹配索引错误：增加迭代通常不能修复根因。

因此应画出多个 $I_{max}$ 下的 BLER 曲线，而不是只观察一个 SNR 点。

可以定义迭代预算的边际收益：

$$
\Delta P_{\mathrm{BLER}}(I)
=P_{\mathrm{BLER}}(I)-P_{\mathrm{BLER}}(I+\Delta I)
$$

以及每轮额外代价对应的收益：

$$
\eta_I
=\frac{\Delta P_{\mathrm{BLER}}(I)}{\Delta I}
$$

当 $\eta_I$ 在目标 SNR 区域接近零时，继续增加最大迭代次数的主要效果可能只是增加尾延迟，而不是显著改善可靠性。

## 收敛轨迹

除最终迭代次数外，可以记录每轮：

- syndrome 重量 $w_s^{(t)}$。
- 当前硬判决与参考码字的汉明距离（仅仿真可用）。
- 后验 LLR 的最小、最大和平均绝对值。
- 通过 CB-CRC 的码块数。
- 变量节点或边消息的变化量。

参考码字只能用于离线分析，不能作为真实接收机的停止条件。收敛轨迹有助于区分“逐步接近但预算不足”和“从第一轮起就因索引/LLR 错误而不收敛”。

## 复杂度与延迟

若 Tanner 图边数为 $|\mathcal{E}|$，一次迭代的消息更新复杂度可粗略表示为：

$$
\mathcal{O}(|\mathcal{E}|)
$$

固定最大轮数时，最坏情况复杂度约为：

$$
\mathcal{O}(I_{max}|\mathcal{E}|)
$$

实际延迟还受到以下因素影响：

- flooding 或 layered 调度。
- QC 层数和提升因子 $Z$。
- SIMD/硬件并行度。
- LLR 和边消息的量化位宽。
- 早停比例和码块并行数量。
- 软缓冲区读写与缓存命中率。

报告吞吐量时，应同时给出每码块平均轮数或每信息比特的计算量，不能只给理论上限。

## 尾延迟与吞吐量

平均迭代次数可能掩盖少量长尾码块。建议同时报告：

- 中位数和 P95/P99 实际迭代次数。
- `max_iter` 占比。
- 早停比例。
- 每码块或每传输块的平均延迟。
- 每秒译码的信息比特数。

设实际迭代次数随机变量为 $I$，则实时系统还应关注：

$$
P_{\mathrm{max}}=\Pr(I=I_{max}),
\qquad
I_{p}=\inf\{x:\Pr(I\le x)\ge p\}
$$

其中 $I_p$ 是 $p$ 分位迭代次数。$P_{\mathrm{max}}$ 可反映达到预算上限的比例，$I_{0.95}$ 和 $I_{0.99}$ 可用于估计尾延迟。

在并行解码中，一个批次的尾延迟可能由最慢码块决定；只报告平均值会高估实时系统的处理能力。

## 译码停止状态

建议将每个码块至少分为以下状态：

| 状态 | 含义 |
|---|---|
| `early_stop_syndrome` | 校验方程提前满足 |
| `early_stop_crc` | CRC 检查提前通过 |
| `max_iter_success` | 达到最大轮数但最终正确 |
| `max_iter_failure` | 达到最大轮数仍失败 |
| `invalid_input` | LLR、长度或结构参数不合法 |

状态命名不是标准字段，但有助于区分算法性能和接口错误。`invalid_input` 不应计入普通信道噪声导致的 BLER。

## 迭代次数实验设计

固定基图、提升因子、码率、码块长度、调制、信道和随机种子策略，仅改变 $I_{max}$：

| $I_{max}$ | BLER | BER | 平均迭代次数 | 早停比例 | 平均延迟 |
|---:|---:|---:|---:|---:|---:|
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |

应至少覆盖一个低、中、高 SNR 区域，并记录每个点的总块数和失败块数。若使用 Min-Sum，还应固定归一化系数、偏移量和 LLR 量化范围。

## 自适应迭代策略

工程实现可以根据校验残差、LLR 变化或历史译码状态分配迭代预算，例如：

- 常规块使用较小的初始上限。
- 检测到校验残差下降但未满足时增加预算。
- 对高可靠块快速早停。
- 对低可靠块使用更高上限或交给重传流程。

自适应策略必须使用独立验证集比较，避免因为不同停止规则改变了 BLER 统计口径。

自适应预算还要设置最坏情况上限，避免异常输入导致无界延迟。对于硬件或在线系统，应把 `invalid_input`、软缓冲区不足和真实未收敛分开统计。

一个自适应策略的比较应同时满足：

$$
P_{\mathrm{BLER}}^{\mathrm{adaptive}}
\le P_{\mathrm{BLER}}^{\mathrm{baseline}}+\delta
$$

并报告平均工作量、P95/P99 延迟和最大预算。只要通过牺牲错误率换取较低平均迭代次数，就不能简单称为“译码优化”。

## 常见误区

1. 最大迭代次数不是每个码块实际执行的迭代次数。
2. 早停后继续执行到最大轮数会增加延迟，但未必改善输出。
3. 只增加迭代次数不能修复 LLR 符号、率匹配或基图选择错误。
4. 不同调度下相同的迭代数字不一定代表相同计算量。
5. 只报告 BLER 不报告平均迭代次数，无法评价复杂度收益。
6. 译码器输出一个码字不等于成功；必须结合校验状态和 CRC 判决。
7. layered 与 flooding 的一次迭代工作量不同，不能只按迭代数直接比较吞吐量。
8. 平均迭代次数低不一定代表 BLER 好，可能是错误的早停条件过早接受了错误码字。

## 最小验证

1. 固定所有链路参数，只扫描 $I_{max}$。
2. 记录每个码块的实际迭代次数和停止原因。
3. 比较 BLER、BER、平均迭代次数和延迟。
4. 翻转 LLR 符号，确认增加迭代不会掩盖接口错误。
5. 在高 SNR 下验证早停比例上升，在中低 SNR 下观察迭代预算的边际收益。
6. 同时报告平均、P95/P99、最大迭代次数和停止原因分布。
7. 分别比较 syndrome 早停、CRC 早停和固定迭代的 BLER/延迟代价。
8. 对 flooding/layered 采用各自的工作量指标，避免用相同迭代数作不公平结论。
