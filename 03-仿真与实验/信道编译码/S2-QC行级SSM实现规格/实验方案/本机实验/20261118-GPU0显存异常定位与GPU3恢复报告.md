## 结论与当前状态

异常已隔离到 **GPU0 的显存数据读写路径**，不局限于 MLP、SSM、NMS、噪声公式或速率恢复算子。独立程序不建立译码器、不计算信道，只将 CPU 随机字节复制到显存再读回，在同一分配块上，两轮分别检出 **374、371 个错误字节**。同一程序在空闲 GPU3 上四轮累计检查 **80 GiB**，错误为 **0**。

这足以判定 GPU0 不适合继续承担本项目的正确性实验，但尚不足以仅凭应用层证据区分物理显存、控制器或驱动的具体故障部件。项目已迁移 GPU3；没有执行系统驱动升级、GPU reset 或影响其他用户的操作。GPU0 硬件修复仍需设备维护处理。

## 证据链

1. 原 endpoint 在 `torch.isfinite(u).all()` 失败。shard05 单独重放曾通过，直接重试后在 shard08 再次失败，说明仅重试不可靠。
2. 增强捕获在 BG1、1.5 dB、shard11 的 NMS 分支发现 **输入已非有限**；MLP 参数仍有限，eager 解码也受同一输入污染。
3. channel probe 在 shard16、调用对应译码批之前即发现输入 NaN。保存的 `6250×13056` 数组在坐标 `(4976,4569)` 出现位型 `0x7fffffff`；译码前后输入逐位未变。
4. 全量配对核查发现 MLP seed29 的 BG2 **160/160 分片**样本哈希及 NMS 四项逐帧指标重现；BG1 已有 **11/11 分片**均不重现。影响不止 NaN，还存在有限值损坏。
5. 独立 CPU FP32 信道精确重现历史 seed17 的 BG1 shard00 样本哈希：`0dbb04df5ce376e06ec44caf854b249e130ef7a150040848daa4a7a4d1aab703`。GPU0 原始 LLR 捕获与 CPU 参考相差 93 个元素，最大差异约 11.234，远超舍入误差。
6. 不建 CUDA 图的固定输入速率恢复，100 次完整 shard 检查均通过；保留图资源后逐级捕获出现 bits 或 recovered tensor 损坏。图改变内存布局可暴露问题，不能据此认定 CUDA graph 或 index_add 本身有错。
7. 独立字节读写程序在 GPU0 分配的第16块（每块256 MiB）检出可重复错误，两组不同随机字节仍集中在相同区域；其他块正常。程序只使用分配、复制和 CPU 比较，未调用项目模型/信道/恢复逻辑。
8. 同软件环境的 GPU3 对照，四轮 80 GiB 零错误；原失败分片、链路和模型检查随后通过。

第7项日志和实际命令：`diagnose-20261118-vram-transport/{launch.json,stdout.log,stderr.log,exit.json}`，退出码1，诊断数据 `recovery-20261118-rate-recovery/probe_vram.json`。GPU3 对照：`verify-20261118-gpu3-memory/`，退出码0。

## 修复、保留与执行检查

本次采用**迁移计算设备**解决执行环境故障，保持同一数学定义和冻结实验设置。没有 NaN 替换、丢弃失败帧、重抽噪声、放松现有正确性门槛或更换选定 checkpoint。

- 将 MLP seed29 旧 BG1 目录中的23个文件（含11个分片）整体迁入恢复目录 `quarantined-test-artifacts/ldpc_B4096_R1-2_Q2/`。迁移前后核对 SHA256；它们不再作为有效配对观测使用，原始证据保留。
- 保留已独立核对的 BG2 160 个分片、100万帧，不重复记为新增观测。
- 原 test/pipeline 失败目录移入 `test-mlp-seed29-failed-retry02/`、`pipeline-failed-retry02/`；此前失败与诊断目录继续保留。没有将退出码改为成功。
- 新 `runner-recovery-20261118-gpu3.py` 只改变该项目的设备 UUID，保留 detached supervisor、独立 stdout/stderr、命令、PID、session 和真实退出码记录。
- 新 `guarded_endpoint.py` 在每个新测试分片译码前，核对 CPU FP32 与 GPU 恢复后 LLR **逐位一致**，并核对历史 seed17 样本哈希；不一致即保留原数组并失败，不替换输入。
- 新 `guarded_training.py` 为后续训练与验证增加 CPU 输入对拍。标量 SNR 验证逐位核对；每帧不同 SNR 的训练信道沿用现有 `check_channel.py` 的绝对误差 `<1e-5` 门槛。新检查最初过严地要求跨设备逐位相等，实测 CPU SIMD/CUDA 向量运算舍入差最大仅 `1.9073486328125e-6`，已保存该诊断；原项目门槛未改变。训练原样执行，不使用 CPU 结果代替 GPU 输入。
- 后续每次新50k机制训练前增加独立显存读写门；原训练的有限性、梯度、状态界、重载和独立审计门继续执行。
- 恢复调度时修正资源记账：旧脚本将“小时”常数直接与秒相加后再除3600，且归档尝试易遗漏。新脚本对 launch/exit 去重计时，保守计入中断的12.8203小时及归档失败/诊断；恢复前约使用54.4小时，原160小时上限不变。

外部 adapter 只增加检查，不更改训练更新、模型、学习率、裁剪、固定网格、帧预算、T20、早停或 fallback 规则。已完成历史 stage 只核验并跳过，新 stage 才使用 GPU3/检查入口。适配器源文件和实际命令单独归档，避免用冻结核心哈希掩盖执行入口变化。
