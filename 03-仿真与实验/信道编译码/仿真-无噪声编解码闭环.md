# 仿真-无噪声编解码闭环

> [!abstract] 一句话结论
> 无噪声闭环是验证 CRC、Polar/LDPC 编码、率匹配、软输入译码和比特顺序的第一道测试；它只能证明实现链路在理想条件下自洽，不能证明在噪声、时变信道或标准全部边界下性能正确。

## 实验目标

验证发送端和接收端在没有随机噪声、信道增益已知且参数完全匹配时，能够逐比特恢复原始信息。该实验优先捕获确定性接口错误：

- CRC 覆盖范围、位序或多项式错误。
- Polar 信息集合、冻结位或 SCL 路径状态错误。
- LDPC 基图、提升因子、校验矩阵或译码初始化错误。
- 率匹配索引、交织、打孔/缩短和重复合并错误。
- 调制比特顺序、解扰和 LLR 符号错误。

## 测试范围

建议分别测试：

| 链路 | 最小覆盖场景 |
|---|---|
| LDPC | 单码块、多码块、不同 RV、打孔/重复和 filler |
| Polar | SC、SCL、CRC-Aided SCL、$E<N$、$E=N$、$E>N$ |
| BCH/PBCH | 固定 MIB、系统帧号和物理候选 |
| DCI/PDCCH | 固定 DCI 格式、RNTI、候选和聚合等级 |
| UCI | 短 UCI、Polar UCI、PUCCH/PUSCH 复用分支 |

不要只使用全零输入；全零输入可能掩盖某些异或、交织、扰码和符号错误。

## 参数账本

| 参数 | 记录内容 |
|---|---|
| 随机输入 | 信息长度、固定向量或随机种子 |
| CRC | 类型、长度、覆盖范围、位序和掩码 |
| 编码器 | LDPC BG/$Z$ 或 Polar $N/K$/信息集合 |
| 率匹配 | $E$、RV、交织和显式索引映射 |
| 物理层 | 调制、扰码、资源映射和 LLR 约定 |
| 信道 | 单位增益、无噪声、理想同步和理想 CSI |
| 译码器 | 算法、最大迭代次数、列表大小和早停 |

长度链应闭合：

$$
A\rightarrow K\rightarrow N\rightarrow E\rightarrow N\rightarrow K\rightarrow A
$$

其中 $A$ 是有效载荷长度，$K$ 是编码输入长度，$N$ 是母码长度，$E$ 是物理发送长度。每个箭头都应有可检查的中间向量。

## 推荐流程

```text
生成非全零信息比特
    ↓
附加 CRC
    ↓
LDPC 或 Polar 编码
    ↓
率匹配、交织和扰码
    ↓
无噪声调制/物理映射（可选）
    ↓
理想解调得到带符号 LLR
    ↓
解扰和逆率匹配
    ↓
LDPC/SC/SCL 译码
    ↓
CRC 与原始信息比较
```

调试时先跳过物理波形，只测试编码器到译码器的 LLR 接口；随后再加入调制、资源网格和 OFDM。分层加入组件能缩小故障范围。

## 通过标准

对每个测试向量至少检查：

- 编码输出长度和母码坐标正确。
- 逆率匹配后的 LLR 与发送母码坐标一致。
- 信息比特 BER 为 0。
- 相关 CRC 通过。
- LDPC syndrome 为 0，或 Polar 候选状态为 `crc_pass`。
- 译码器在预期的早停条件下结束。
- 译码输出不是依赖偶然的全零初始化。

无噪声条件下允许 LLR 使用有限但足够大的幅度；同时应测试零 LLR 和不同幅度，确认实现没有错误依赖某个特殊数值。

## 错误注入矩阵

| 注入错误 | 预期表现 | 应定位到 |
|---|---|---|
| LLR 全部取反 | 译码失败或输出系统性错误 | LLR/调制接口 |
| 交换两个信息位 | CRC 失败或信息比特错位 | 信息集合装载 |
| 错一位率匹配索引 | 译码失败 | 率匹配 |
| 重复 LLR 覆盖而非累加 | $E>N$ 性能或闭环异常 | 逆率匹配 |
| 改变冻结位 | Polar CRC 失败 | 冻结集合 |
| 改变 LDPC 一块循环移位 | syndrome 不为零 | QC-LDPC |
| CRC 位序反转 | CRC 失败 | CRC 接口 |
| 错误 RV | 重传闭环失败 | HARQ/率匹配 |

## 最小测试集合

1. 非全零短信息、无 CRC 的小型线性码闭环。
2. 含 CRC 的 Polar $N=2^n$ 小码长闭环。
3. 含单码块和多码块的 LDPC 闭环。
4. $E<N$、$E=N$ 和 $E>N$ 的率匹配闭环。
5. 不同 RV 的发送序列和逆率匹配闭环。
6. 物理调制前后分别比较 LLR 和硬判决。
7. 每种错误注入至少运行一个正例和一个负例。

## 常见误区

1. 无噪声通过不代表 AWGN 下 LLR 标定正确。
2. 全零输入通过不代表比特顺序和扰码处理正确。
3. 译码器输出合法码字不等于恢复了发送信息，仍需 CRC 或参考向量比较。
4. 直接使用硬判决输入会掩盖软信息和重复 LLR 合并错误。
5. 只检查长度不检查坐标映射，无法捕获交织和率匹配错误。
